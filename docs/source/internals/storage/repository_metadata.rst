Repository metadata schema
==========================

The ``repository_metadata`` column stores the virtual file hierarchy of a node repository as JSON.
The JSON is generated by :meth:`aiida.repository.repository.Repository.serialize` and read by :meth:`aiida.repository.repository.Repository.from_serialized`.
The value is always a JSON object.
The empty repository is represented by ``{}``.

Top-level structure
-------------------

A directory is encoded as a JSON object.
A directory may contain the key ``"o"``.
The value of ``"o"`` is a mapping from object name to object metadata.
An empty directory is encoded as ``{}``.
A directory may also contain ``"deleted": true`` when it is marked for deletion.

A file is encoded as a JSON object with the key ``"k"``.
The value of ``"k"`` is the repository backend key for the file content.
A file may also contain ``"deleted": true`` when it is marked for deletion.

No path separators are stored explicitly.
The hierarchy is represented by nesting through ``"o"``.
The names in an ``"o"`` mapping are single path components.

Schema by example
-----------------

An empty repository:

.. code-block:: json

    {}

A repository with one file at ``file.txt``:

.. code-block:: json

    {
      "o": {
        "file.txt": {
          "k": "<backend-key>"
        }
      }
    }

A repository with a nested file at ``folder/sub/file.txt``:

.. code-block:: json

    {
      "o": {
        "folder": {
          "o": {
            "sub": {
              "o": {
                "file.txt": {
                  "k": "<backend-key>"
                }
              }
            }
          }
        }
      }
    }

A repository with an empty directory at ``empty``:

.. code-block:: json

    {
      "o": {
        "empty": {}
      }
    }

A file marked for deletion:

.. code-block:: json

    {
      "o": {
        "file.txt": {
          "k": "<backend-key>",
          "deleted": true
        }
      }
    }

A directory marked for deletion:

.. code-block:: json

    {
      "o": {
        "folder": {
          "o": {
            "file.txt": {
              "k": "<backend-key>"
            }
          },
          "deleted": true
        }
      }
    }

Semantics
---------

The schema is intentionally compact.
Directories are identified by the absence of ``"k"``.
Files are identified by the presence of ``"k"``.
The ``"deleted"`` flag is optional.
If ``"deleted"`` is absent, the object is considered active.
If ``"deleted"`` is ``true``, the object is considered marked for deletion.

Objects marked for deletion are skipped by :meth:`aiida.orm.nodes.repository.NodeRepository.list_objects` and :meth:`aiida.orm.nodes.repository.NodeRepository.list_object_names`.
Stored nodes still retain the metadata entry until storage maintenance hard-deletes the unreferenced backend object.
If another node still references the same backend object through a non-deleted entry, maintenance will not delete the backend object and will report the conflict.

Notes for developers
--------------------

This schema is an internal storage format.
It is stored in ``db_dbnode.repository_metadata`` for the SQL backends.
The backend key stored in ``"k"`` is repository-backend specific.
For the disk-objectstore backend it is the content hash.
For the sandbox backend it is an internal temporary object key.

Consumers that need a path-to-key mapping can use :meth:`aiida.repository.repository.Repository.flatten`.
Code that needs to ignore soft-deleted entries should use ``Repository.flatten(..., include_deleted=False)``.
